# 実装仕様: lab-executor v2.9 — export 結果の instrument / sweep / measurement フィルタ

> **この仕様は Codex に実装を委ねるための自己完結ドキュメントです。**
> `tests/test_v2_9_filter_spec.py` が全 PASS になり、実機 E2E
> (別途 Claude Code 側で実施) が通れば完了です。
> **修正が必要になった場合も Codex 側で対応してください。**

## 1. 背景 / 目的

v2.16〜v2.18 で各測定 row に `instrument` / `sweep_index` / `sweep_value`
列を載せた。100 台規模・多点 sweep の Job では結果 row が数千行になり、
「instrument X の row だけ」「sweep_index=3 の点だけ」を取り出したい。

現状 `get_experiment_results` / `export_experiment_results` は全 row を
返す/書き出すのみで、列で絞り込む手段が無い。両ツールは **experimental**
なので signature 追加が許される。本 v2.9 で **フィルタ引数**を足す。

- 新 MCP tool は追加しない (stability 7/43 不変)。
- 既存引数・response 構造は壊さない (引数は optional 追加、filter 未指定で
  従来と完全同一の挙動)。

## 2. 追加するフィルタ引数

`get_experiment_results` / `export_experiment_results` の **両方**に、
以下の optional 引数を末尾追加する (順序は既存引数の後ろ):

| 引数 | 型 | default | 意味 |
|------|----|---------|------|
| `instrument` | `str` | `""` | row の `instrument` 列と完全一致する row のみ |
| `sweep_index` | `int \| None` | `None` | row の `sweep_index` 列が一致する row のみ |
| `measurement` | `str` | `""` | row の `measurement` 列と完全一致する row のみ |

- `""` / `None` の引数は **そのフィールドで絞らない** (no-op)。
- 複数指定は **AND** で結合 (instrument AND sweep_index AND measurement)。
- `sweep_index` は `0` が有効値なので、未指定は `None` で表す
  (`0` と `未指定` を区別するため。空文字や `-1` を使わないこと)。
  FastMCP/Pydantic は `int | None = None` を受け付ける。

## 3. 純粋ヘルパ `_filter_rows` を新設 (export.py)

MCP に依存せず単体テストできるよう、フィルタは純関数に切り出す:

```python
def _filter_rows(
    rows: list[dict],
    *,
    instrument: str | None = None,
    sweep_index: int | None = None,
    measurement: str | None = None,
) -> list[dict]:
    """結果 row を instrument / sweep_index / measurement で AND フィルタ。

    空文字 / None のフィルタはそのフィールドで絞らない。
    sweep_index フィルタが指定された場合、row の sweep_index が None の行は
    除外される (一致しないため)。
    """
    out = rows
    if instrument:
        out = [r for r in out if r.get("instrument") == instrument]
    if sweep_index is not None:
        out = [r for r in out if r.get("sweep_index") == sweep_index]
    if measurement:
        out = [r for r in out if r.get("measurement") == measurement]
    return out
```

## 4. 各ツールへの組み込み

### 4.1 `get_experiment_results`

`_extract_result_rows(...)` で `all_rows` を得た **直後・pagination の前**に
`_filter_rows` を適用する。`total` / `has_more` は **フィルタ後**の件数で
計算する (pagination はフィルタ済み集合に対して効く)。

```python
all_rows = _extract_result_rows(job_mgr, job_id, include_monitor=...)
all_rows = _filter_rows(
    all_rows, instrument=instrument or None,
    sweep_index=sweep_index, measurement=measurement or None)
total = len(all_rows)
...
```

`data` に適用フィルタを echo するキーを追加 (additive):

```python
data["filters"] = {
    "instrument": instrument or None,
    "sweep_index": sweep_index,
    "measurement": measurement or None,
}
```

### 4.2 `export_experiment_results`

`_extract_result_rows(...)` の **直後**に同じく `_filter_rows` を適用。
書き出す `rows` と返り値の `rows` (件数) は **フィルタ後**。返り値 `data`
に同じ `filters` キーを追加する。CSV/JSONL の fieldnames は
`RESULT_COLUMNS` のまま (列は減らさない、行だけ絞る)。

- フィルタ引数は optional 追加のみ。未指定で従来と完全同一の rows / 件数。
- `RESULT_COLUMNS` は変更しない (列の増減なし)。
- `export_experiment_bundle` は **フィルタ対象外** (再現性 bundle は
  全 row を保持すべき。引数を足さない)。
- visa-mcp 側 shim copy への同期は **v2.9 スコープ外** (別タスク、Claude)。
- DSL schema 変更なし。新規 SQLite table / migration 不要。
