## 1. 背景 / 目的

`get_job_live_view` / `get_experiment_results` は **Job 全体**の集約
ビューを返すが、100 台規模・多 instrument の sweep では「instrument
別」「sweep point 別」の切り口が欲しい、というレビュー要求がある。

v2.6 では **新 MCP tool 1 件** `get_job_instrument_view` を追加し、
job_steps / measurement_cache から **instrument 単位**に再集計した
観察ビューを返す。既存 tool は一切変更しない (純追加)。

## 2. 新 MCP tool: `get_job_instrument_view`

### シグネチャ

```python
async def get_job_instrument_view(
    job_id: str,
    instrument: str | None = None,   # 省略時は全 instrument
) -> dict
```

`lab_executor.tools.observation.register_tools(mcp, job_mgr)` 内に
`@mcp.tool()` として登録する。

### 返り値 (response envelope `make_envelope("ok", data=...)`)

```jsonc
{
  "status": "ok",
  "data": {
    "job_id": "job_xxx",
    "job_status": "completed",            // rec.status.value
    "instruments": [
      {
        "instrument": "$psu",             // step result の instrument 値 (alias or raw resource)
        "step_count": 12,                 // この instrument の job_steps 件数
        "ok_count": 12,
        "failed_count": 0,
        "last_status": "ok",              // 最後の step の status
        "last_command": "measure_voltage",
        "last_raw_response": "+3.99600E+00",
        "last_value_numeric": 3.996,      // parsed.value_numeric か fields.value (取れれば)
        "last_step_index": 24,
        "last_ended_at": "2026-05-29T...",// ISO8601 (取れれば、無ければ null)
        "measurements": [                 // この instrument の query 系 step を時系列で
          {
            "step_index": 7,
            "command": "measure_voltage",
            "raw_response": "+9.96000E-01",
            "value_numeric": 0.996,       // 取れなければ null
            "status": "ok",
            "ended_at": "..."             // 無ければ null
          }
          // ...
        ]
      }
      // ... instrument ごとに 1 要素
    ],
    "instrument_count": 2,
    "schema_version": "2.6"
  }
}
```

- `instrument` 引数を指定した場合は `data.instruments` を
  **その 1 件だけ**にフィルタして返す (該当が無ければ空配列 +
  `instrument_count: 0`)。

## 3. データソースと抽出規則

`job_mgr.store.list_steps(job_id)` が返す各 step dict
(`{id, job_id, target_id, step_index, step_type, status,
started_at, ended_at, result, error}`) を使う。

- **instrument の決定**: `step["result"]` (dict) の中の
  `"instrument"` キー。これは
  `_run_experiment_plan_job` の step_completed event 同様、
  command step の result に含まれる。
  `result.instrument` が無い step (wait など) は **どの instrument
  にも属さない**ものとして集計から除外する。
- **status**: `step["status"]` (`"ok"` / `"failed"` 等)。
- **command / raw_response**: `step["result"]["command"]` /
  `step["result"]["raw_response"]`。
- **value_numeric**: 以下の優先順で取得 (取れなければ null):
  1. `step["result"]["parsed"]["value_numeric"]`
  2. `step["result"]["parsed"]["fields"]["value"]` (数値なら)
- **measurements 配列に入れる step**: `result.command` があり、かつ
  `result` に `raw_response` を持つ (= query 系) step のみ。
  `set_*` のような write step は measurements に入れない
  (ただし step_count / ok_count には数える)。
- **時系列順**: `step_index` 昇順。

### `_extract_instrument_views(store, job_id, instrument=None)` ヘルパ

`lab_executor/tools/observation.py` (または別 helper module) に
純関数として実装し、`get_job_instrument_view` から呼ぶこと。
**この純関数は単体テストの対象**なので、`store` を受け取り
`list[dict]` (instruments 配列相当) を返すシグネチャにする:

```python
def _extract_instrument_views(
    store, job_id: str, instrument: str | None = None,
) -> list[dict]:
    ...
```

## 5. 後方互換・スコープ外 (やらないこと)

- 既存 `get_job_live_view` / `get_job_summary` /
  `get_experiment_results` の response 構造変更は **禁止**。
- DSL schema (`dsl_version=0.8`) 変更は **禁止**。
- 新規 SQLite table / migration は **不要** (既存 job_steps で足りる)。
- sweep point 番号の厳密な復元 (compiled IR からの逆引き) は
  v2.6 スコープ外。`step_index` 順で十分。
- per-instrument の monitor_data 統合は v2.7 候補 (今回は job_steps
  のみ)。
