# 実装仕様: lab-executor v2.7 — per-sweep-point 観察 API

> **この仕様は Codex に実装を委ねるための自己完結ドキュメントです。**
> `tests/test_v2_7_per_sweep_spec.py` が全 PASS になり、実機 E2E
> (別途 Claude Code 側で実施) が通れば完了です。
> **修正が必要になった場合も Codex 側で対応してください**
> (Claude Code は spec / 実機検証 / レビューに専念します)。

## 1. 背景 / 目的

v2.6 (v2.16.0/2.16.1) で **instrument 別**の観察 API を入れた。
レビュー要求「instrument 別 / **sweep 別**の観察」の残り半分、
**sweep point 別**の観察 API を v2.7 で追加する。

sweep job (DSL の `sweep` step) は body を value 数だけ複製して実行
するが、現状 job_steps からは「どの step がどの sweep point に属する
か」を復元できない。v2.7 では:

1. compile 時に各 sweep body step へ sweep 文脈
   (`sweep_index` / `sweep_param` / `sweep_value`) を付与
2. DSL 実行時にそれを step result へ永続化 (v2.16 の instrument 注入と
   同じパターン)
3. 新 MCP tool `get_job_sweep_view` で sweep point 別に再集計

recipe path に sweep は無いので **DSL path のみ**対応する。

## 2. データモデル変更

### 2.1 IR step に sweep 文脈フィールド追加

`src/lab_executor/experiment_ir/step.py` の `CommandStep` に
**optional** フィールドを追加 (後方互換、default None):

```python
sweep_index: int | None = None      # sweep の何番目の point か (0 始まり)
sweep_param: str | None = None      # sweep parameter 名 (例: "v")
sweep_value: Any = None             # その point の値 (例: 2.0)
```

`WaitStep` 等の他 step 型には追加しなくてよい (sweep view は
command/query step のみ対象)。

### 2.2 compiler が sweep 展開時にセット

`src/lab_executor/dsl/compiler.py` の sweep 展開ループ
(`_convert_step` 内、`isinstance(s, DSLSweepStep)` の箇所、現在
`for i, v in enumerate(values)`) で、展開した各 `CommandStep` に
`sweep_index=i`, `sweep_param=s.parameter`, `sweep_value=v` をセット
する。

- sweep の **外側** (pre/post step) の CommandStep は sweep 文脈を
  持たない (None のまま)。
- ネストした sweep は v2.7 スコープ外 (現状 DSL は sweep ネストを
  サポートしない前提)。

### 2.3 DSL 実行時に step result へ永続化

`src/lab_executor/job/manager.py:_run_experiment_plan_job` で、
step result を `record_step_completed` する前に sweep 文脈を result へ
注入する (v2.16 の instrument 注入と同じ場所・同じパターン):

```python
for key in ("sweep_index", "sweep_param", "sweep_value"):
    val = getattr(step, key, None)
    if val is not None and isinstance(result, dict) and key not in result:
        result[key] = val
```

注: `sweep_value` が `0` / `0.0` の場合も「値あり」として保存すること
(`is not None` 判定なので 0 は保存される。`sweep_index=0` も同様)。

## 3. 新 MCP tool: `get_job_sweep_view`

### シグネチャ

```python
async def get_job_sweep_view(job_id: str) -> dict
```

`lab_executor.tools.observation.register_tools` 内に `@mcp.tool()` で
登録 (docstring に `(experimental, v2.7)` 明記)。

### 純関数 `_extract_sweep_views(store, job_id) -> list[dict]`

`observation.py` に純関数として実装 (単体テスト対象)。
`store.list_steps(job_id)` のみ読み、sweep 文脈を持つ step を
`sweep_index` ごとに集計する。

### 返り値 (make_envelope("ok", data=...))

```jsonc
{
  "status": "ok",
  "data": {
    "job_id": "job_xxx",
    "job_status": "completed",
    "is_sweep_job": true,             // sweep 文脈を持つ step が 1 つでもあれば true
    "sweep_param": "v",               // 代表 param 名 (最初に見つかったもの。無ければ null)
    "sweep_points": [
      {
        "sweep_index": 0,
        "sweep_value": 1.0,
        "step_count": 2,              // この point の command step 数
        "instruments": ["$psu", "$dmm"],  // この point で触れた instrument (出現順 unique)
        "measurements": [            // query 系 (raw_response あり) のみ、step_index 昇順
          {
            "instrument": "$psu",
            "command": "measure_voltage",
            "raw_response": "+0.996E+00",
            "value_numeric": 0.996,   // 取れなければ null
            "step_index": 7,
            "status": "ok"
          }
          // ...
        ]
      }
      // sweep_index 昇順
    ],
    "sweep_point_count": 3,
    "schema_version": "2.7"
  }
}
```

- sweep 文脈を持つ step が 1 つも無い job は
  `is_sweep_job: false`, `sweep_points: []`, `sweep_point_count: 0`,
  `sweep_param: null` を返す (error にしない)。
- job 不在は `make_envelope("error", ...)` で `not_found`。

## 4. 抽出規則 (v2.6 と揃える)

- step ごとに `result` (dict) を読む (`store.list_steps` の `result`)。
- sweep 文脈: `result.sweep_index` が `None` の step は **除外**。
- instrument: `result.instrument` (v2.16 で永続化済み)。
- measurements に入れる step: `result.command` があり、かつ
  `result` に `raw_response` キーを持つ (query 系)。write 系は
  `step_count` には数えるが measurements には入れない。
- value_numeric: `result.parsed.value_numeric` → `result.parsed.fields.value`
  の順 (v2.6 の `_value_numeric_from_result` をそのまま再利用してよい)。
- 並び: sweep_points は `sweep_index` 昇順、measurements は
  `step_index` 昇順。

1. `tests/test_v2_7_per_sweep_spec.py` が **全 PASS**。

6. 既存 MCP tool / API / DSL schema は一切変更しない (純追加)。

## 6. 後方互換・スコープ外

- 既存 `get_job_instrument_view` / `get_job_live_view` 等は変更禁止。
- DSL schema (`dsl_version=0.8`) 変更禁止 (sweep 文脈は IR / 永続化
  result の追加 field のみ)。
- 新規 SQLite table / migration は不要。
- ネスト sweep / parallel 内 sweep は v2.7 スコープ外。
- recipe path は対象外 (sweep 非対応)。

## 7. 実機 E2E (Claude Code 側で実施、Codex は不要)

PMX35-3A + 7563 の 1→3V sweep job を流し、
`get_job_sweep_view(job_id)` が 3 つの sweep point を返し、各 point に
$psu (measure_voltage) と $dmm (read_measurement) の measurement が
入ることを確認する。
