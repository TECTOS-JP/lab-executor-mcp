# 実装仕様: lab-executor v2.8 — export dir の env 上書き + sweep/instrument 列

> **この仕様は Codex に実装を委ねるための自己完結ドキュメントです。**
> `tests/test_v2_8_export_spec.py` が全 PASS になり、実機 E2E
> (別途 Claude Code 側で実施) が通れば完了です。
> **修正が必要になった場合も Codex 側で対応してください。**

## 1. 背景 / 目的

2 つの課題を v2.8 で解決する (どちらも `tools/export.py` 内)。

**課題 A: export 先が固定で書けない環境がある。**
`DEFAULT_EXPORT_DIR = Path.home() / ".visa-mcp" / "exports"` 固定で、
`_safe_export_path` が起動時に `base.mkdir(...)` する。home が書けない
制限環境 (Codex の検証環境) で `PermissionError` になり export が
使えない。env で書き込み可能な場所へ向けられるようにする。

**課題 B: v2.16/v2.17 で永続化した instrument / sweep 情報が
export に出ない。**
`RESULT_COLUMNS` に `instrument` 列はあるが、sweep_index /
sweep_value が無い。100 台規模で「どの instrument の・どの sweep 点の
測定値か」を CSV / pandas で解析するには、これらの列が必要。

## 2. 課題 A: export dir を env で上書き可能にする

### 2.1 `_resolve_export_dir() -> Path` を新設

```python
def _resolve_export_dir() -> Path:
    """export 先ディレクトリを優先順で決定する。
    1. $VISA_MCP_EXPORT_DIR (運用上書き)
    2. ~/.visa-mcp/exports (従来 default)
    """
    raw = os.environ.get("VISA_MCP_EXPORT_DIR", "").strip()
    if raw:
        return Path(raw).expanduser()
    return Path.home() / ".visa-mcp" / "exports"
```

- **毎回呼ぶ** こと (module import 時に固定しない)。env を後から
  設定しても効くようにする。`DEFAULT_EXPORT_DIR` 定数を直接使うのを
  やめ、`_safe_export_path` 内で `_resolve_export_dir()` を呼ぶ。

### 2.2 `_safe_export_path` の mkdir 失敗を error 化

`base.mkdir(parents=True, exist_ok=True)` が例外を投げたら、
**raise せず** structured error dict を返す (関数は
`tuple[Path | None, dict | None]` を返す既存シグネチャを維持):

```python
try:
    base.mkdir(parents=True, exist_ok=True)
except OSError as e:
    return (None, {
        "error_class": "export_dir_not_writable",
        "message": (
            f"export ディレクトリを作成できません: {base} ({e}). "
            f"VISA_MCP_EXPORT_DIR で書き込み可能な場所を指定してください。"),
        "recoverable": True,
        "details": {"export_dir": str(base)},
        "recommended_next_actions": [
            {"action": "set_export_dir_env",
             "reason": "VISA_MCP_EXPORT_DIR=<書き込み可能 path> を設定"},
        ],
    })
```

- 「output_path は base 配下である必要がある」既存の security check は
  維持する (base が `_resolve_export_dir()` の結果に変わるだけ)。

## 3. 課題 B: sweep_index / sweep_value 列を追加

### 3.1 `RESULT_COLUMNS` に追加

既存タプルの末尾に 2 列追加 (順序は末尾、既存列の順は変えない):

```python
RESULT_COLUMNS = (
    "timestamp", "target_id", "instrument", "measurement",
    "value", "unit", "step_index", "step_path",
    "sweep_index", "sweep_value",   # v2.8 追加
)
```

### 3.2 `_extract_result_rows` で各 row に sweep 値を載せる

各 step の `result` (dict) から `sweep_index` / `sweep_value` を読み、
row の `common` 部 (timestamp/target_id/instrument/step_index/step_path
を作っている箇所) に追加する。存在しなければ `None`。

```python
common = {
    ...,
    "sweep_index": r.get("sweep_index"),
    "sweep_value": r.get("sweep_value"),
}
```

- `instrument` 列は既に `r.get("instrument")` で populate される
  (v2.16 で step result に instrument が載るようになったので、実 Job
  でも値が入る)。**この挙動を壊さないこと。**
- CSV / JSONL 出力は `RESULT_COLUMNS` で回しているので、列追加だけで
  両形式に反映される (`export_experiment_results` の writer は
  `RESULT_COLUMNS` を fieldnames に使う)。
